# Handasa Governance Core
## نواة هانداسا للحوكمة وتدقيق التصويت
أدوات قراءة فقط لصياغة مقترحات الحوكمة ومراجعة التصويت دون تنفيذ معاملات.

نواة خاصة لصياغة مقترحات الحوكمة وتدقيق التصويت **للقراءة فقط**. لا يطلق هذا المشروع مقترحات عبر RPC، ولا يوقع أو ينفذ أو يرسل معاملات، ولا يثبت أن أي محفظة تملك سيطرة حاسمة.

## المكونات

- `proposal_manager.py`: ينشئ مسودات قابلة للمراجعة فقط، ويرفض raw calldata.
- `vote_tracker.py`: يحسب التأييد والمعارضة والنصاب باستخدام أوزان التصويت المقدمة، مع وسمها بأنها غير متحققة مستقلًا.
- `alerts.py`: قوالب Discord إشعارية فقط، مع منع mentions.
- `governance.config.example.json`: قوالب إعداد Snapshot وTally مع تعطيل التنفيذ.
- `.github/workflows/governance-audit.yml`: فحوص دورية كل 5 دقائق، دون صلاحية كتابة أو تنفيذ.

## Snapshot وTally

القالب في `governance.config.example.json` يحتاج إلى `space` وعناوين عامة موثقة قبل أي إعداد فعلي. لا توجد مفاتيح أو حسابات أو عقود مضمّنة. استخدم المنصات الرسمية يدويًا أو عبر تطبيق مصرح به، وراجع النصوص والآثار قبل النشر.

## Multi-Sig

أي تنفيذ مستقبلي يجب أن يمر عبر محفظة إدارة متعددة التوقيع ومراجعة مستقلة. هذا المستودع لا يحتوي على signer أو private key أو raw calldata، ولا يوفر مسارًا لتجاوز التوقيعات المتعددة.

## التشغيل المحلي

```bash
python -m unittest -v
python proposal_manager.py
python vote_tracker.py
```

## Secrets

ضع `DISCORD_WEBHOOK` في GitHub Actions Secrets فقط إذا أردت تنبيهات Discord. لا تضع مفاتيح خاصة أو عبارات استرداد أو أسرار توقيع في المستودع أو Workflow.

## حدود الدقة

أوزان التصويت وحالة النصاب لا تصبح حقائق إلا بعد جلبها من مصدر رسمي مع تحديد الشبكة واللقطة الزمنية والاستراتيجية. القيم الموجودة في `votes.example.json` تجريبية وليست بيانات مستثمرين حقيقية.
